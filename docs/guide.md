# Director与Agent的协作指南

## 角色与授权

Director提出目标和验收方式，对方向、授权、重要产品与架构取舍、主观体验、风险接受和正式版本负责。Agent调查事实、准备候选、实现、测试、记录并报告。一个人可以兼任多个工作角色；独立评审Agent必须没有参与被评候选实施，换会话不能使原作者变成独立评审者。

目标清楚、边界已授权、客观检查通过的工作可以自主完成并事后报告。出现新的真实外部影响或重要取舍时，先把候选、影响、证据和恢复方式准备到可审阅，再请求具体决定。不要逐个模板字段请求审批。

## 冷启动与文档

先写目标、非目标、成功标准、现有事实和限制，再建立最小仓库骨架、Agent入口与验证命令。不要提前复制整套业务系统。

一项事实只在负责位置完整维护：REQ解释为什么改变；SYS/CAP/CRS保存当前设计；ADR保存重要取舍理由；Issue保存问题去向；Loop保存本轮过程；版本选择实际交付范围。链接导航不代表递归必读，历史记录不替代当前设计。

## 按风险选择流程

|实际情况|采用方式|
|---|---|
|当前任务能直接修正并验证的低风险问题|直接修改、验证、报告|
|需要单独调查、排期或长期追踪|Issue|
|改变长期承诺、业务规则、权限、数据或交付范围|REQ与受影响设计|
|重要长期选择与替代旧决定|ADR并更新当前设计|
|需要持续协调、重要候选与证据|ACL、DFL或ERL|
|准备正式交付|固定提交、验收实际范围、授权并创建版本标签|

这些对象不是必经流水线。换Agent、跨会话或修改可见界面不会自动产生REQ或Loop。

## 实施、反馈与独立评审

ACL（Agentic Coding Loop）由Agent实施：固定来源和启动基线，写目标、非目标、停止和完成条件，实现、定点测试、统一验证，保存实际纳入提交，再按依据结束。

DFL（Developer Feedback Loop）由Director主导真实使用：固定环境、角色、数据与候选；每次候选变化新增Attempt。只观察固定对象，修复交给实施工作。

ERL（Engineering Review Loop）由独立Agent检查固定提交或差异。发现要有复现或依据，不能把推测当确认缺陷。修复保留原评审基线并另行实施。

新Loop使用一个主记录，执行开始后的计划是快照；变化追加原因，不把结果反写为原计划。DFL/ERL先使用局部Finding，需要跨工作单元追踪时才升级全局Issue。

Loop状态：Ready → In Progress → Review → Completed；未结束时可Withdrawn，Review可回到In Progress。Completed只表示本轮按依据结束，不表示没有发现问题或已经发布。`verified`要求客观完成条件与必需检查通过；`director`记录新的主观验收、正式决定或风险接受，不能以这个字段伪造授权。

## 并行与交接

Director或协调者划分边界，固定各任务起点、依赖和合入顺序。每个Agent使用独立worktree，避免同时编辑共享登记表。共享编号由协调者串行分配；合入后再同步注册表与双向链接。独立worktree不等于权限扩大。

交接保存目标、授权范围、完整提交、工作树差异、已运行和失败检查、阻塞及下一动作。不能只依赖聊天记忆，也不因换会话补造管理对象。

## 追踪与版本

长期约束使用PRD/DOM/ARCH/SEC稳定编号；同一约束修订保持编号，拆分或对象改变才新编号。JSON保存设计与验证关系，Markdown为生成视图。direct判断要求本身，supporting只提供相关证据；摘要变化需要重新审查语义与验证，刷新摘要不能代替测试。

版本验收固定实际提交、范围、证据、排除项与遗留风险。目标版本不证明交付，环境部署不证明版本形成，CI不替代实机体验或恢复验证。正式标签需要Director具体授权，标签不覆盖或复用。本次提取不创建正式发布标签。
